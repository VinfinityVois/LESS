# SFace: подготовка выборки и калибровка порога

В LESS предусмотрены два отдельных шага: генерация similarity scores локально по парам изображений и офлайн-оценка ROC/FAR/FRR. Ни датасет, ни кадры, ни embeddings не должны попадать в Git.

## 1. Подготовка датасета

Храните изображения и manifest вне папки репозитория. Для каждого тестового сравнения укажите:

    label,image_a,image_b,condition,camera

- genuine — два независимых изображения одного участника;
- impostor — изображения разных участников;
- image_a / image_b — относительные пути внутри dataset-root;
- condition — например bright, low_light, side_angle, glasses;
- camera — обезличенная метка камеры/модели.

Не используйте ФИО, NFC UID, номера пропусков или другие идентификаторы в именах файлов и метках. Разделяйте участников между calibration и holdout выборками: изображения одного человека не должны одновременно попадать в обе выборки.

## 2. Генерация оценок SFace

Из папки backend после установки зависимостей и моделей:

    python scripts/generate_face_scores.py manifest.csv --dataset-root D:\LESS-BIOMETRIC-TEST\images --output D:\LESS-BIOMETRIC-TEST\scores.csv

Скрипт:
- использует локальные YuNet/SFace ONNX-модели;
- проверяет, что пути изображений остаются внутри dataset-root;
- требует ровно одно обнаруженное лицо в каждом изображении;
- кэширует embeddings в оперативной памяти на время процесса;
- записывает только label, cosine similarity, condition и camera;
- отказывается читать датасет или писать scores внутри репозитория LESS.

Если для пары не удалось обнаружить лицо или построить embedding, обработка останавливается с номером строки. Исправьте manifest/изображение и повторите запуск; не заменяйте ошибку нулевой оценкой.

## 3. ROC/FAR/FRR отчёт

    python scripts/evaluate_face_threshold.py D:\LESS-BIOMETRIC-TEST\scores.csv --target-far 0.001 --output D:\LESS-BIOMETRIC-TEST\report.json

Будут созданы JSON-отчёт и SVG-график ROC рядом с JSON. При наличии condition и camera отчёт также содержит разрезы по этим группам.

## 4. Интерпретация

- FAR — доля impostor-пар, ошибочно принятых при данном пороге.
- FRR — доля genuine-пар, ошибочно отклонённых.
- TAR = 1 - FRR.
- ROC AUC характеризует разделимость genuine/impostor score на конкретной выборке.
- EER в отчёте — дискретное приближение по доступным порогам.
- Wilson CI показывает неопределённость оценки на конечной выборке, но не устраняет смещение выборки.

Текущий production threshold SFace 0.363 остаётся неизменным. Рекомендация evaluator — только материал для инженерного review. Перед изменением production-порога нужны независимая holdout-проверка, анализ по условиям/камерам, проверка доверительных интервалов и документированное согласование.
